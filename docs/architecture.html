Agent framework & command gateway apps/worker + apps/api

Agent runtimework queue (Postgres FOR UPDATE SKIP LOCKED) → agent loop (Anthropic SDK, model routed by task shape) → step-by-step transcripts; deterministic keyless fallbacks for every task
Command gatewaytyped commands, schema + permission + idempotency checks; standing authority auto-executes, everything that moves money or leaves the building waits for a human
Releases & evalsversioned skills, immutable releases (draft → evaluated → active), eval suites gate promotion; behaviour change = new release. Telemetry (D14): per-period tokens/items/cost via the rate card; eval_summary rollups survive history flushes, raw transcripts and old eval runs are prunable
every economic change becomes a business event — two entry postures, one pipe

Finance Data Platform fdp schema · data store + ledger combined

Finance-initiated events (P2P, O2C) arrive with account-coded deltas attached; business-initiated events (month-end ticks, future insurance-style feeds) arrive bare and the deterministic engine derives the deltas from versioned parameter sets.

Event storeappend-only, idempotent on (source_system, source_event_key), immutable by trigger; failed events retry safely
Derivation enginedeterministic, versioned, no model calls; parameter sets immutable once active; replay reproduces history
Movement ledgerone immutable row per event × account; the authoritative delta history
Journalsbalanced double-entry per event, enforced by a deferred DB constraint; SDJ (system) vs GOJ (human-approved) classes
LES — Live Economic Statederived views over movements: GL by account + subledger by economic object (invoice, payment, bank line). Continuously live; what agents reason over.
LRS — Locked Reporting Statelock = physical snapshot · certify = immutable, decision-ready · supersede = restatement. Deferred — lands as one more action on the R2R dashboard.
Invariants, checked by verifyFdp: no movement without an event · per-event deltas balance to zero · movements mirror journal lines exactly · LES sums to zero · no failed events outstanding.
derived aggregations only — reporting never recalculates economics

Flow of a pound: module event → fdp.event → fdp.movement + erp.journal_line (same deltas, enforced) → LES views → statements. Corrections are new events; certified history (once LRS lands) is never edited.
